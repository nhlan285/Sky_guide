# Core domain validation — P2-D01

Import the public types and validators from `index.ts`. Modules have no React, network, adapter or public dataset dependency: `primitives` defines ID/source vocabulary, `provenance` validates source records/collections/references, `money` validates CurrencyAmount, `time` validates PartialTime/DateTime, and `validation` contains the shared result and internal field helpers.

Validators take unknown input and return `{valid: true, value}` or `{valid: false, errors: [{path, code, message}]}`. Paths contain field names/array indexes. Codes and traversal order are stable; messages contain no raw values. Successful record results project declared fields rather than copying extra payloads. This structural projection is not the publication/rights allowlist gate (P2-D11).

DATA_SCHEMA limits sourceId to registered K01–K15; K15 is the explicitly approved public ThatSkyApplication utility source. Callers also supply a `ReadonlySet<SourceId>`: an enum-valid ID absent from that registry fails. `validateSourceRecords` rejects duplicate record IDs; `validateProvenanceIds` checks downstream references in a supplied ID set and rejects duplicates/empty references. Only technical fixtures may explicitly opt into `allowEmpty: true`; real domain provenance must be non-empty.

Nullable fields are required keys with null for unknown, per the schema's `T?` notation. Missing keys are not silently filled. Source URLs/metadata use the documented string/null shape; these validators do not verify URL authenticity, fetch a source, infer permission, or prove publication eligibility. IDs must be non-blank, without normalization or restrictions on source naming beyond the source enum.

CurrencyAmount accepts non-negative **safe integer numbers** and null; numeric strings, non-finite/fractional/unsafe values fail without coercion. Null, explicit zero and free status are different: this module never infers `free` or converts currency. JavaScript cannot represent arbitrary large integer counts exactly, so unsafe numbers are rejected. `other` requires a non-blank original source label. Decimal IAP prices are a separate later contract.

Calendar dates use `YYYY-MM-DD` with Gregorian leap/day checks. Instants use extended calendar date plus `T` clock `HH:mm[:ss[.fraction]]` and explicit `Z` or numeric offset (`±HH`, `±HHmm`, `±HH:mm`); comma fractions are also accepted. Clock components must be within 00–23/00–59/00–59; numeric offsets within 00–23 hours and 00–59 minutes. Leap seconds, 24:00 and other ISO representations are not parsed by this module. Values are preserved, never passed through permissive Date.parse normalization. A timezone metadata string alone cannot make an offset-less instant valid. Date precision can retain timezone=null; unknown precision preserves source text without making it an instant. No timezone from locale, LA offset, event schedule or countdown is inferred.

Run `pnpm test` (`node --test tests/data/*.test.mjs`) on the pinned Node 24 runtime. Node natively strips erasable TypeScript for the production modules; test files use `node:test`/`node:assert` with synthetic fixture labels only. TypeScript separately checks source modules with `pnpm typecheck`. Explicit `.ts` imports and `allowImportingTsExtensions` keep Node tests and Vite/noEmit checking compatible without another package.
